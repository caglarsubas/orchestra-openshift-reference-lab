# Lab service publication

This procedure publishes the release-validation receiver and synthetic tenant
kit as immutable, keyless-signed GHCR source artifacts. It does not mirror an
image into Harbor, perform the certification vulnerability scan, satisfy RHTAS
admission, change GitOps, deploy a Pod, or produce campaign evidence.

## Contract

The locked policy is
`config/lab-service-publication.lock.json`. It requires:

- an exact reviewed `main` revision and first workflow attempt;
- one release name matching `lab-services-v0.1.0-rc.N`;
- distinct immutable release-plus-revision tags for both services;
- exactly one `linux/amd64` image manifest and one bound attestation manifest;
- BuildKit `mode=max` SLSA provenance and an SPDX SBOM generated by the exact
  scanner image digest;
- keyless Cosign signatures issued only to the exact main-branch publication
  workflow; and
- a strict payload-free observation with every mirror, admission, deployment,
  campaign, and certification claim fixed to `false`.

The embedded Syft version is recorded as transport metadata. It is not the
certification risk scan. That later gate uses the separately locked
certification-runner Trivy/Syft policy and produces reviewed risk evidence.

## Preconditions

1. The intended source revision is the current immutable `main` revision.
2. Exact-main CI is green and the change has completed normal code review.
3. GitHub Actions can write packages in the repository owner's GHCR namespace
   and mint an OIDC identity for Sigstore.
4. Neither derived immutable tag exists in either image repository.
5. A new release candidate number is selected. Never retry a partial
   publication with the same release or rerun the same workflow attempt.

## Publish

```bash
main_sha="$(git rev-parse origin/main)"
release="lab-services-v0.1.0-rc.1"

gh workflow run lab-service-publication.yml \
  --ref main \
  -f expected_main_sha="$main_sha" \
  -f release="$release"
```

Monitor the exact run to completion. The workflow fails closed when a tag
already exists, registry absence cannot be distinguished from an authorization
or transport error, an image digest is malformed, an OCI index contains an
unexpected platform/manifest, either required attestation is missing, or the
keyless signature cannot be replayed.

The workflow uploads only
`lab-service-publication-observation-<run>-1`. It contains source-tree, image,
manifest, attestation, workflow, and policy digests. It contains no registry
credential, OIDC token, image payload, application payload, Secret, or
certification claim.

## Independent verification

Download the observation from the exact successful run and verify its strict
contract:

```bash
make verify-lab-service-publication REPORT=restricted/lab-service-publication-observation.json
```

Independently replay each image signature against the exact workflow identity
and issuer, and inspect the release-plus-revision tag and digest. Record the
workflow URL and report digest in the change review; do not commit the
downloaded observation.

Only after this verification may a separate reviewed change move
`config/lab-services.lock.json` from `source-only` to a digest-bound
`published` state. That change must remove only the
`published-signed-image` blocker. Harbor mirroring, certification risk review,
RHTAS admission, GitOps reference, deployment, and campaign evidence remain
separate later states.

## Partial failure

A run can publish one image before failing on the other. Treat every resulting
tag as immutable and unadmitted. Do not delete, overwrite, or reuse it. Fix the
cause in source, merge and prove a new exact-main revision, then publish a new
release candidate. A partial run has no complete observation and cannot update
the service inventory.
